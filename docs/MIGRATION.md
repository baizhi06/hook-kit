# 迁移手册：从内联补丁到四个接口

写给要改自己插件的人。顺序很重要，每一步都能单独回滚。

## 第 0 步：先量，不要凭印象

| 数什么 | 怎么数 | 典型结果 |
| --- | --- | --- |
| 决策入口 | 多少处调用「让她醒来说话」 | 10 个，该压成 1 个 |
| 发送出口 | 多少处真正往外发消息 | 35 处，该压成 1 个 |
| 提示词块 | 多少个独立函数在拼提示词 | 7 个，但硬编码在一行 `return [a,b,c]` |
| 生成后出口 | 有没有统一出口 | 多数项目**没有** |

最后一行通常是空白，也最值得先补。

## 第 1 步：只做登记，不写代码

把现有插点列成表，标清楚：接口类型、只读还是改写、影响不影响缓存、顺序。

做完这一步，通常会砍掉一半——很多插点其实该合并，没必要迁。

## 第 2 步：抽空接口

装上 `createHookKit()`，把四个接口接到调用点上，**所有扩展先不注册**。

跑一次基线：行为必须和改造前逐字一致。

## 第 3 步：逐块迁

按「已经收口成单入口」的优先：

1. `gate`（决策）——本来就只有一个调用点时最难的是共情，不是改代码；
2. `context`（提示词块）——七个函数改成七个 `register`，拼装顺序从硬编码变成 meta.order；
3. `afterSend`——记账、捕获待办这类副作用最容易搬；
4. `incoming` / `transform`——最后搬。

每搬一块跑一次回归，能单独回滚。

## 第 4 步：才动行为

「把七块改成两块」属于**改行为**，不是改架构。它必须放在第 3 步之后，因为只有接口稳定了，才能分清退化是行为改猛了还是接线接错了。

## 第 5 步：冻结接口 + 存基线

冻结的是四样东西，不是函数名：

**签名**（传什么、返回什么）、**顺序**（谁先谁后）、**读写权限**（只读还是能改）、**缓存失效规则**（改了别人怎么知道）。

基线怎么做：一个 `verify.mjs`，跑语法、预设、路由状态码、工具清单、提示词**结构**快照。

快照只存小节标题和字数、不存正文，所以能安全提交进公开仓库。

## 前人踩过的坑

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 日志每条重复两遍 | 自己写文件 + 进程管理器又收一遍 stdout | 只留一处输出 |
| 静音后连主人都喊不动 | 闸门把手动唤醒也拦了 | `manual` / `admin` / `force` 放行 |
| 群里看到「对主人的看法」 | 记忆或印象没按会话过滤 | 注入前按 `conversationKey` 过滤 |
| 改备注名断线 5 秒 | 任何白名单变更都重启桥接 | 只在成员变化时重启 |
| 升级后提示词变了才发现 | 没有基线 | 迁移前后快照逐字对比 |
| 面板能改任意配置 | 开关接口不校验路径 | 白名单路径 |
| 接口加太多 | 顺序和缓存键失控 | 固定四到六个，够了 |
| 直接删护栏 | 「简化」把限流去重删了 | 降级成默认关的开关，别删 |

## 一句话

先量，再登记；先抽空接口跑基线，再逐块迁；行为改动放最后。
